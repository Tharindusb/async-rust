Lesson 0002 · Async Rust

First .await over TCP

Run a mini-Redis server, then use Tokio to connect → set → get — each step waits with .await.

Why this matters for your mission

Mini-Redis is the official Tokio teaching project. Your first real network Future is the same skill you will grow into a GET/SET server later. Interview talking point: “I waited on TCP with .await on Tokio.”

The picture

Terminal A — server

Keeps listening. Accepts your client’s TCP.

mini-redis-server

Terminal B — you

Each .await pauses until that step finishes.

connect → set → get → print

Reminder from lesson 0001: without .await, those calls would only build Futures and do nothing.

Do this

  • 1
    Install the teaching server

    Once: cargo install mini-redis (puts mini-redis-server on your PATH).

  • 2
    Start the server

    New terminal: mini-redis-server. Leave it running. Optional check: mini-redis-cli get foo → (nil).

  • 3
    Run this crate’s client

    In the repo: cargo run. Code is already in src/main.rs (from Tokio Hello Tokio).

Win: you should see got value from the server; result=Some(b"world"). If connect fails, the server is probably not running.

What the code is doing

use mini_redis::{client, Result};

#[tokio::main]
async fn main() -> Result<()> {
    let mut client = client::connect("127.0.0.1:6379").await?;
    client.set("hello", "world".into()).await?;
    let result = client.get("hello").await?;
    println!("got value from the server; result={:?}", result);
    Ok(())
}
  • connect(...).await? — TCP Future; ? means “if it failed, return the error from main.”
  • set / get — more Futures over that connection; each needs its own .await.
  • We use the mini-redis client crate now so we can practice awaiting before we build the server ourselves.

Sources — summarised for you

  • Tokio — Setup Install mini-redis with Cargo; run mini-redis-server; sanity-check with mini-redis-cli get foo. Mini-Redis is for learning Tokio, not production Redis.
  • Tokio — Hello Tokio (primary) First app: connect, set, get — each with .await. Async looks sync; the thread is not blocked while waiting. Lazy Futures still apply.
