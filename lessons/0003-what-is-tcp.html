Lesson 0003 · Async Rust

What is TCP?

The pipe under connect().await: a private phone line. Handshake first, then bytes in order — that wait is a Future.

Why this matters for your mission

You already ran the mini-Redis client. Interviewers will ask what connect().await is waiting for. Answer: a TCP connection — not “magic async.” You also saw Connection refused when the server was down. That was TCP saying: nobody picked up.

Analogy: a private phone line

A postcard can vanish or arrive out of order. TCP is a phone call: you both agree you are on the line, then you talk in sequence. Missed words get repeated. That is “reliable, in-order byte stream.”

IETF: RFC 9293 §2.2.

Tie it to your code

client::connect("127.0.0.1:6379").await?;

connect builds a Future. .await drives it until the handshake succeeds (Ready) or fails (refused). set / get are more Futures on that same pipe.

Sources — summarised for you

  • RFC 9293 (TCP spec) TCP = reliable, in-order byte stream over IP segments. Connection oriented. Handshake is three messages because both sides must share and confirm starting sequence numbers.
  • MDN — TCP / handshake Two hosts exchange a stream. Delivery is guaranteed and ordered. Setup: SYN → SYN-ACK → ACK. Then data (your SET/GET) can flow.
  • Tokio — Hello Tokio TCP connect can take time; async suspends the task instead of blocking the thread. The code still looks like a normal call plus .await.
