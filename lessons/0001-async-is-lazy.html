Lesson 0001 · Async Rust

Async is lazy

One idea that unlocks Tokio: calling an async fn builds a Future — it does not run the body until you .await it.

Why this matters for your mission

Interviewers and code reviews poke this exact point. Treat async fn like a normal call and you write code that “silently does nothing.” Nail this before mini-Redis TCP.

The picture

Normal fn

Call = cook now. Body runs before the next line.

call → runs → done

async fn → Future

Call = recipe card. Cooking starts at .await.

call → Future → await → runs

A Future is a value that represents work that is not done yet. Something must drive it — usually .await on Tokio’s runtime.

Step through the demo

Same shape as src/main.rs (from Tokio’s Hello Tokio):

  • 1
    let op = say_world();

    Future built. Body has not run. Console: (nothing)

  • 2
    println!("hello");

    Sync code runs now. Console: hello

  • 3
    op.await;

    Runtime drives the Future. Body runs. Console adds world 

async fn say_world() {
    println!("world");
}

#[tokio::main]
async fn main() {
    let op = say_world(); // Future only
    println!("hello");
    op.await;             // NOW body runs
}

Try it: uncomment op.await; in src/main.rs if needed, then cargo run. You should see hello then world. Comment .await out again — world vanishes (Rust may warn the Future is unused).

What #[tokio::main] is doing

An async fn main cannot start alone. The macro turns it into a normal fn main that starts a runtime and block_ons your async main. The runtime is the engine that drives Futures.

Sources — summarised for you

You do not need to read the long pages. Here is what they say that matters for this lesson:

  • Tokio — Hello Tokio (primary) Calling async fn does not run the body; it returns a Future. .await starts execution. Rust async is lazy — different from many other languages. #[tokio::main] builds a runtime and block_ons your async main.
  • Rust Book §17.1 A Future is a value that may not be ready now. async / await compile into Future types (like for compiles into Iterator). You usually .await; you rarely touch poll yourself.
  • std::future::Future Futures are inert until polled. Skip the trait details for now — mission keeps deep Pin/poll out of scope until the tutorial needs them.
